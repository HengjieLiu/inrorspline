## Theory Summary

Let `C` be a vector of cubic B-spline control coefficients and `U` be the dense
displacement field. Let `B` denote the fixed cubic B-spline expansion operator:

```text
U = B C
```

For DirectCP, `C` is the trainable parameter vector. Under a local SGD view with
loss `L(U)`, the dense update induced by a dense displacement-space gradient
`g_U = dL/dU` is:

```text
s = B^T g_U = dL/dC
Delta C_DirectCP = -eta s
Delta U_DirectCP = -eta B s
                  = -eta B B^T g_U
```

Thus DirectCP has:

```text
CP-space tangent kernel:     I
dense displacement NTK:      B B^T
```

For SINR, the control coefficients are generated by an INR/SIREN:

```text
C = h_theta(Q)
```

where `Q` are fixed control-point coordinates. Let:

```text
J_theta = d h_theta(Q) / d theta
K_C     = J_theta J_theta^T
```

`K_C` is the CP-space empirical NTK of the coefficient generator. The local
SGD-style update is:

```text
Delta C_SINR = -eta J_theta J_theta^T s
              = -eta K_C s

Delta U_SINR = -eta B K_C s
              = -eta B J_theta J_theta^T B^T g_U
```

Thus SINR has:

```text
CP-space tangent kernel:     K_C = J_theta J_theta^T
dense displacement NTK:      B K_C B^T
```

This is the precise version of the comparison:

```text
DirectCP:  B B^T
SINR:      B J_theta J_theta^T B^T
```

The practical experiment should compare the action of these kernels on actual
registration gradients, not materialize either dense matrix.

## Conditioning Claim

DirectCP is well conditioned in CP parameter space under the local SGD metric:

```text
K_C_DirectCP = I
condition number = 1
```

SINR is constrained by the control-generator Jacobian. For OASIS cps4 rank 9,
the completed runs report:

```text
DirectCP cps4 CP coefficients: 388,161
SINR SIREN parameters:         133,379
```

Therefore:

```text
rank(K_C_SINR) <= 133,379
nullity(K_C_SINR) >= 388,161 - 133,379 = 254,782
```

So in the full cps4 CP coefficient space, the SINR CP tangent kernel is
rank-deficient while DirectCP's CP-space kernel is identity. This supports a
local tangent-space claim:

> The INR control generator induces a rank-deficient and potentially anisotropic
> CP-space tangent kernel. Compared with DirectCP's identity kernel in control
> space, this can worsen local conditioning and can explain why SINR requires
> smaller learning rates.

This should be phrased as a local NTK/SGD mechanism diagnostic. Adam,
regularization, finite training, and image nonlinearity can alter the realized
optimization path, so the claim should not be overstated as a global optimizer
proof.

## Main Metrics

Given the same CP-space gradient `s` at a fixed SINR state:

```text
x = B s
y = B K_C s
```

where `x` is the DirectCP dense update direction from that gradient and `y` is
the SINR dense update direction from the same gradient.

### 1. Dense Update Direction Agreement

```text
D_U = cos(y, x)
    = <B K_C s, B s> / (||B K_C s|| ||B s||)
```

Interpretation:

- `D_U` near `1`: SINR moves in nearly the same dense DVF direction as DirectCP.
- Low or negative `D_U`: the INR generator changes the update direction.

### 2. Scalar-Rescaled Residual

Fit the best scalar from the DirectCP dense update to the SINR dense update:

```text
alpha = <y, x> / <x, x>
R_U   = ||y - alpha x|| / ||y||
```

Interpretation:

- Low `R_U`: SINR is approximately DirectCP plus a learning-rate rescale on this
  task gradient.
- High `R_U`: the INR kernel adds a distinct direction/bias.

### 3. Amplification

```text
A_C = ||K_C s|| / ||s||
A_U = ||B K_C s|| / ||B s||
```

Interpretation:

- `A_U` near `100` would align naturally with an empirical LR gap like
  DirectCP `1e-2` versus SINR `1e-4`, under a local SGD step-size view.
- Very small `A_C` or `A_U` implies damping or nullspace projection.
- Very large values imply gradient amplification and potential LR sensitivity.

### 4. PSD And Rayleigh Checks

Because `K_C = J_theta J_theta^T` is positive semidefinite:

```text
s^T K_C s >= 0
lambda_s = (s^T K_C s) / (s^T s)
```

The implementation should report `dot_s_Ks`, `lambda_s`, and whether the PSD
check passes within numerical tolerance.

### 5. Lightweight Spectrum Diagnostics

Do not form `K_C`. Use matrix-vector products:

```text
v -> K_C v = J_theta J_theta^T v
```

Recommended diagnostics:

- exact rank upper bound: `rank(K_C) <= num_sinr_params`
- exact nullity lower bound: `num_cp_coefficients - num_sinr_params`
- power-iteration estimate of `lambda_max(K_C)`
- random-direction Rayleigh percentiles for `v^T K_C v / v^T v`
- random-direction amplification percentiles for `||K_C v|| / ||v||`

Avoid reporting a naive full condition number because the full CP-space
condition number is infinite when `K_C` is rank-deficient. Prefer:

```text
nullity lower bound
lambda_max estimate
p95 / p50 random Rayleigh ratio
p95 / p05 random Rayleigh ratio, if p05 is not numerically zero
actual-gradient amplification A_C and A_U
```

## What This Can And Cannot Prove

This experiment can support:

- SINR's coefficient INR induces a rank-deficient CP tangent kernel.
- SINR locally amplifies, damps, or rotates actual registration gradients
  relative to DirectCP.
- The observed SINR learning-rate sensitivity is consistent with local NTK
  amplification or anisotropy.
- If `D_U` is high and `R_U` is low, the dominant useful dense update bias is
  still the shared cubic B-spline parameterization.

This experiment cannot by itself prove:

- a global optimizer convergence theorem,
- that Adam follows exactly the SGD/NTK update,
- that `B B^T` globally dominates `B K_C B^T` for all possible gradients,
- or that the LungCT multistage capture-range effect is caused only by this
  kernel.

### Core Implementation Steps

1. Load the dataset/case using the existing OASIS or LungCT runner helpers.
2. Build the SINR control generator and control-coordinate lattice.
3. Load the target SINR state:
   - `init`: rebuild from seed `1`,
   - `final`: load existing `model_state.pt`,
   - `replay`: retrain and save requested checkpoint states.
4. Compute control output:

   ```text
   C = h_theta(Q)
   ```

5. Treat `C` as a leaf tensor and compute:

   ```text
   s = dL(B C) / dC
   ```

   Primary gradient should be data/image loss only. Secondary total-loss rows
   may include the training regularizer.

6. Compute `K_C s = J_theta J_theta^T s` without forming `J_theta`:

   ```text
   p  = J_theta^T s      via autograd VJP
   Ks = J_theta p        via torch.func.jvp or equivalent
   ```

7. Decode:

   ```text
   x = B s
   y = B Ks
   ```

8. Compute `D_U`, `R_U`, `A_C`, `A_U`, `s^T K_C s`, `lambda_s`, norm summaries,
   and matrix-size/rank-bound summaries.
9. Probe spectrum with repeated `v -> K_C v` products when requested.
10. Write CSV/JSON summaries, plots, and a short markdown report.

### JVP/VJP Implementation Notes

Preferred implementation:

- Use PyTorch functional APIs to flatten/unflatten SIREN parameters.
- Use `torch.func.functional_call` plus `torch.func.jvp` if available.
- Use `torch.autograd.grad(C, params, grad_outputs=s)` for `J_theta^T s`.

Fallback:

- If `torch.func` is unavailable in the Docker image, use
  `torch.autograd.functional.jvp` with a stateless functional call.
- Do not use finite differences for production metrics; finite differences are
  only acceptable for a tiny unit/smoke validation.
